# RunBeat — 모바일 러닝 기록 앱

마지막 과제 BR-B의 1차 모바일 웹 앱입니다. 10번 논문 「음악 장르와 템포에 따른 러닝 수행 차이 탐색」에서 사용한 운동 시간·거리·평균 페이스 측정 방식을 스마트폰에서 직접 체험할 수 있도록 구현했습니다.

**구현 범위:** 업로드한 9:16 디자인 스케치를 기준으로 만든 러닝 대시보드. 우상단 메뉴 버튼은 안내 메시지만 표시합니다. 기록 작성/모음은 달력형 RunBeat Diary로 구현했고, 플레이리스트 작성 화면만 아직 보류했습니다.

## 실행 방법
1. 웹에서 RunBeat 공개 주소에 접속하거나 저장소의 index.html 파일을 엽니다.
2. 모바일에서 **기록 시작**을 누르고 위치 권한을 허용하면 GPS 측정을 시작합니다.
3. **일시정지/기록 재개** 버튼으로 제어하고 **기록 종료**로 최종 결과를 확인합니다.

GPS는 HTTPS 또는 localhost에서 사용 가능하며, 파일 직접 열기에서는 동작하지 않을 수 있습니다.

## 제공 기능
- 모바일 세로형 반응형 화면과 라이트/다크 모드
- 운동시간 타이머와 기록 시작·일시정지·재개·종료
- GPS를 이용한 이동 거리, 평균 속도(km/h), 평균 페이스(분:초/km)
- 0.75m 보폭 가정을 사용한 **추정 걸음 수** (센서 실측값 아님)
- 음악 장르 **직접 입력**: 클래식, 시티팝, J-POP, Artcore 등 자유롭게 기입
- GPS 불가 시 누적 거리를 직접 입력하는 테스트 기능
- 잘못된 입력·위치 권한 거부·GPS 흔들림에 대한 안내
- 우상단 메뉴 버튼: 추후 기능 안내만 표시 (화면 전환 없음). 기록 작성/모음은 메인 화면 하단의 러닝 다이어리 버튼을 사용합니다.

## 테스트 순서
1. **기록 시작** 후 타이머가 증가하는지 확인합니다.
2. **일시정지** 시 타이머가 멈추고 **기록 재개** 후 다시 진행하는지 확인합니다.
3. **GPS가 안 되나요? 거리 직접 입력하기**에서 1.20km를 입력합니다. 1.20km와 약 1,600걸음이 표시되고, 평균 속도·페이스가 계산되는지 확인합니다.
4. 빈 칸, 0, 음수, 1000을 넣으면 계산 대신 오류 안내가 나타나는지 확인합니다.
5. **기록 종료** 후 결과 창이 나타나는지 확인합니다. **📸 캡쳐하기 · 이미지 저장**을 눌러 RunBeat_러닝기록_날짜_시간.png (900×1600px) 파일이 저장되는지 확인합니다. **새 기록 시작하기**를 누르면 새로운 기록을 시작할 수 있습니다.
6. 다크 모드 전환 후 새로고침 시 선택한 테마가 유지되는지 확인합니다.
7. 우상단 메뉴 버튼은 준비 중 메시지만 출력하는지 확인합니다.
8. 공개 URL을 새 시크릿 창에서 열어 로그인 없이 사용 가능한지 확인합니다.

## 종료 결과 이미지 저장
1. 기록을 시작하고 종료 버튼을 누릅니다.
2. 종료 결과 화면의 **📸 캡쳐하기 · 이미지 저장** 버튼을 누릅니다.
3. PC·Android에서는 다운로드 폴더에서 PNG 파일을 확인합니다. iPhone·iPad에서는 iOS 공유 메뉴에서 **이미지 저장** 또는 **파일에 저장**을 선택합니다.
4. PNG에는 기록 종료 시점의 운동 시간·이동 거리·평균 속도·평균 페이스·예상 걸음 수·음악 장르·일시가 포함됩니다. 사진 크기는 **900×1600px(9:16)**입니다.

저장 이미지는 외부 캡처 서비스에 전송되지 않고 브라우저의 Canvas 기능만으로 생성됩니다. 기록 작성/모음 화면은 아직 구현하지 않았습니다.

## RunBeat Diary — 달력형 기록 작성/모음

러닝 화면 아래의 **러닝 다이어리 · 기록 작성/모음** 버튼을 누르면 달력이 열립니다.

1. 달력에서 날짜를 선택합니다. 저장된 러닝 기록이 있는 날짜에는 작은 점이 표시됩니다.
2. 달력 아래 **＋ 새 러닝 일기 작성** 버튼을 누르면 별도의 일기 작성 화면으로 이동합니다.
3. 날짜, 음악 장르(**정해진 목록 없이 직접 입력**), 이동 거리, 운동 시간을 입력합니다. 시간은 09:22 또는 01:09:22 형식입니다.
4. 컨디션, 걷기 횟수, 운동강도(1~10), 메모를 선택적으로 기록한 후 **일기 저장하기**를 누릅니다.
5. 달력의 해당 날짜에서 기록을 확인하고 **수정** 또는 **삭제**할 수 있습니다.
6. 선택한 달의 누적 거리, 러닝 횟수, 거리 가중 평균 페이스가 달력 위에 표시됩니다.
7. 러닝 화면에서 **기록 종료 → 이 기록으로 러닝 일기 작성**을 누르면 거리·시간·음악 장르가 자동으로 입력됩니다.

### 저장 위치 / 주의 사항

- 일기는 localStorage에 저장됩니다(현재 기기의 해당 브라우저). 서버나 Supabase에 전송하지 않습니다.
- **다른 기기와 동기화되지 않습니다.** 브라우저 데이터를 지우거나 시크릿 창을 닫으면 데이터가 삭제될 수 있습니다.
- 이번 단계에는 기록 내보내기/복원 기능이 없습니다. 중요한 기록은 별도로 백업해 주세요.
- 월별 통계는 본인이 저장한 기록을 바탕으로 계산한 것이며 연구 원자료를 의미하지 않습니다.
- 플레이리스트 작성 화면과 음악 추천 기능은 아직 보류했습니다.

### 다이어리 빠른 테스트

1. 오늘 날짜 선택 → **＋ 새 러닝 일기 작성**.
2. 음악 장르에 시티팝, 거리 1.2, 운동 시간 09:22 입력 → 평균 페이스 07:48 /km 확인.
3. 저장 후 해당 날짜에 점과 기록 카드가 나타나는지 확인.
4. 수정에서 장르를 재즈로 변경 후 저장 → 카드 내용이 바뀌는지 확인.
5. 삭제에서 확인 선택 → 기록이 사라지는지 확인.
6. 러닝 측정 후 종료 화면에서 일기 작성 버튼을 눌러 값이 자동으로 입력되는지 확인.
7. 새로고침 후 기록이 유지되는지 확인.
## 한계 및 개인정보
- GPS 측정은 권한·수신 환경에 영향을 받으며 실제 거리와 차이가 생길 수 있습니다. 5m 이하 위치 흔들림 및 비현실적인 급이동을 제외하는 간단한 필터를 적용합니다.
- **예상 걸음 수는 거리를 보폭 0.75m로 나눈 추정값**이며 실제 걸음 센서 데이터가 아닙니다.
- 휴대전화 절전·화면 잠금·브라우저 백그라운드 상태에서는 타이머/GPS 갱신이 제한될 수 있습니다.
- 위치 좌표를 서버에 보내지 않습니다. 로그인·API 키는 사용하지 않습니다. 측정값은 일기에 저장하기 전까지 임시로만 유지되며, 저장한 일기는 브라우저 localStorage에 보관됩니다.
- 앱은 논문의 측정 항목·음악 조건을 활용하되, 특정 음악 장르가 반드시 속도를 높인다고 주장하지 않습니다.

## GitHub Pages 공개하기
1. https://github.com/hwangyunjeong72/RunBeat 저장소를 엽니다.
2. **Settings → Pages**를 선택합니다.
3. **Build and deployment → Deploy from a branch**, Branch는 **main**, Folder는 **/(root)**로 선택한 뒤 Save를 누릅니다.
4. 배포 후 https://hwangyunjeong72.github.io/RunBeat/ 에서 확인합니다. 이 주소는 Pages 설정 및 배포가 성공해야 열립니다.
